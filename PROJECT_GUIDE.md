# CrushReply Project Guide

## Run the app

1. Install Flutter and Android Studio, including an Android SDK and emulator.
2. From this folder run `flutter pub get`.
3. Start an emulator or connect an Android phone with USB debugging enabled.
4. Run `flutter run` to launch CrushReply.
5. Run `flutter analyze` and `flutter test` before sharing a change.

## Source layout

- `lib/main.dart` contains the app root, theme toggle, home UI, category navigation, reply screen, suggestion templates, clipboard actions, and ad/premium presentation placeholders.
- `lib/services/free_usage_service.dart` stores a five-per-day free quota on the device with `shared_preferences`.
- `test/widget_test.dart` covers the paste, navigation, generation, quota display, and copy journey.
- `android/` and `ios/` are the native mobile projects; the other platform folders were generated by Flutter.

## MVP generation behavior

The first version uses local templates and a few simple message cues. It does not call an AI service. For personalized AI, add a server endpoint and call it from a service class; keep API credentials on the server and add loading, retry, timeout, and error states in the app.

## Monetization and release

Premium costs KSh 100 for one calendar month and is paid manually through an M-Pesa STK prompt. Flutter calls the API in `backend/`; the API owns Daraja credentials, receives the payment callback, and only reports Premium after a successful result. Active Premium skips the local five-reply daily cap and placeholder ad slot. This is not automatic recurring billing.

For the web version, `.github/workflows/deploy-web.yml` builds and deploys Flutter Web to GitHub Pages. `render.yaml` deploys the separate Node API with persistent payment storage. GitHub Pages cannot host the Daraja backend or safely store Daraja secrets. Set the GitHub Actions variable `PAYMENT_API_BASE_URL`, deploy the API, and configure its secrets in the API host. See `backend/README.md` for setup and sandbox-first instructions.

The current MVP stores Premium expiry on the device and does not provide accounts, phone ownership verification, or cross-device restore. The server stores the M-Pesa number for subscription renewal. Add authenticated server-side entitlement checks and a payment reconciliation/support process before relying on this for production revenue. The ad slot is still a visual placeholder; live AdMob integration is not included.

Before launch, deploy both GitHub Pages and the API, obtain approved Daraja production credentials, complete payment/refund support and privacy/data disclosures, and verify current Safaricom terms. Publishing a website does not create an Android APK; build and sign Android separately for Google Play or direct download. For Play, configure the final application ID, signing, target SDK, data-safety details, content rating, and store assets.
